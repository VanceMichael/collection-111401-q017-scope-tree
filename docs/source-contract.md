# 门店门户

`/portal` 提供正常浏览器操作。根节点仅包含区域，区域按两条一页懒加载。门店 id 在调区后不变；名称并非身份。父级勾选是动态继承选择，包含未来新增成员；叶子勾选仅代表该门店。视觉上的子项未打勾不表示父级继承失效，“核对范围”展示服务实际采用的集合。

默认业务范围在 fixtures/request.json：只领取 A、C 两个直营网点，不包括加盟门店。必须通过页面交互设置与核对范围；资料交给现有 Archive。可正常读取页面展示和下载结果，不使用控制面代替选择操作。generation=2 将 C 调到东区并新增 D，因此第一次观察树不保证后续范围没有变化。

本地业务 API 是页面自身的数据服务，`/export` 的返回集合才是此次资料对应范围。来源没有自动按“直营”过滤的隐藏选项。

## 本地演练控制

`GET /_health` 返回服务健康状态；`GET /_audit` 仅返回请求路径、方法和体积，不记录凭据。`POST /_control` 接收 JSON，可调整 generation、mode、clock。控制端点只服务于本地演练，不是资料接口，也不是浏览器业务操作入口。每次重新启动服务都会恢复初始数据；生产接入时不部署此控制面。

## 浏览器领取流程（src/collector.mjs）

入口为 `collectScope(base, target, directory)`，CLI 是 `npm run collect -- <门户地址> <范围文件> <收件目录>`，范围文件使用 fixtures/request.json 形态。流程只通过页面控件与页面自身发出的数据请求完成，不直接调用接口改写选择状态，并显式拒绝访问 `/_control`：

1. 打开 `/portal` 后点击“清空选择”，以空范围开始，杜绝历史继承选择带入加盟店。
2. 逐个点击“展开区域”，并反复点击“更多门店”直到按钮消失；展开与翻页以页面自身的 `/tree` 往返和 DOM 增长为准，而不是只看按钮禁用状态。
3. 仅根据页面实际渲染的叶子建立名单，记录每个门店的 id、名称、类型与所属区域；任何指定 id 在全部分页中找不到，或类型与范围不符，都抛出 `ScopeDiscrepancyError` 停止，并附上已观察到的完整名单，不猜测缺失节点。
4. 只勾选目标门店的叶子复选框，从不触碰区域继承框（`data-inherit`），因此未来新增门店与同区加盟店不会被自动纳入。
5. 点击“核对范围”，以 `#scope` 展示的服务端实际集合与目录版本为权威结果；与指定范围存在任何缺少或多出成员即停止。
6. 点击“领取资料”，再次核对 `#result` 中 `/export` 返回的门店集合与目录版本；任一不符或版本在核对后跳变都不交接资料。
7. 核对全部通过后，才把导出内容交给 `Archive` 保存，收据记录来源、目录版本、生效范围与请求范围。

## 目录调版的处理

枚举开始时记录页面展示的目录版本，枚举结束、范围核对、导出三个节点分别复核。若发现版本跳变（门店可能已调区、新增或下架），整轮观察作废、开新页面从头重来，最多重试 3 次；持续无法确认时以 `generation-drift` 原因停止并解释差异，全程不会保存部分结果。
